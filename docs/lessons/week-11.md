## W11D01：跨资产 ETF 核心池、真实无风险利率与 `pandas` 切换

### 1. 为什么升级标的池与历史区间？

前 10 周仅用 `SPY / DIA / QQQ`（2020–2024）做开发基准，存在两个明显局限：
- **高度同源**：三只 ETF 全是美国大盘股，相关性常年 0.85+，很难真正检验动量轮动或分散风控。
- **周期单一**：2020–2024 大部分时间处于美股科技牛市，缺少 2008 级深度熊市与长期低迷阶段。

为此，我们设计一套个人可直接落地的**7 只无杠杆跨资产核心 ETF 池**（成立日均已于 2026-11-25 核验发行商官方资料）：

| 代码 | 资产类别 | 在组合中的核心角色 | 官方成立日期 |
| --- | --- | --- | --- |
| `SPY` | 美国大盘股（标普 500） | 核心权益成长引擎 | 1993-01-22 |
| `QQQ` | 美国科技/纳斯达克 100 | 高弹性成长进攻资产 | 1999-03-10 |
| `EFA` | 发达国际股票（美加外） | 跨区域权益分散 | 2001-08-14 |
| `TLT` | 20+ 年期长期美债 | 通缩/衰退危机避险（对利率极敏感） | 2002-07-22 |
| `IEF` | 7–10 年期中期美债 | 经典股债平衡压舱石 | 2002-07-22 |
| `GLD` | 现货黄金 | 通胀、地缘与货币贬值对冲 | 2004-11-18 |
| `BIL` | 1–3 个月美国国库券 | **现金等价物 / 避风港**（空仓吃利息） | **2007-05-25** |

**为什么公共开发区间起点选 `2007-06-01`（截止 `2024-12-31`，2025 继续封存）？**
- 7 只标的里 `BIL` 成立最晚（2007-05-25）。**绝不在基金成立前伪造行情**，因此取 `2007-06-01` 作为公共起点；2007 下半年正好充当动量/均线预热期，2008 年起完整经历 **2008 全球金融危机、2010s 低利率慢牛、2020 疫情闪崩、2022 高通胀加息“股债双杀”、2023–2024 高利率 AI 牛市**五大宏观周期。
- 在 **2022 年高通胀加息**中，股票（`SPY/QQQ`）和长债（`TLT`）因利率飙升**同时大跌**（传统股债负相关失效），超短久期国库券（`BIL`）几乎不跌；黄金（`GLD`）全年收益大致持平，但 3–11 月盘中最大回撤约 20%，并非“扛住回撤”。真正起避风港作用的是 `BIL`（v2.1 勘误）。
- **封存红线不变**：`2025-01-01` 至 `2025-12-31` 继续封存至 **W21** 一次性评估。

### 2. 无风险利率（$R_f$）与真实超额夏普比率

前 10 周计算夏普比率时默认无风险利率 $R_f = 0\%$，这是低利率时代的陈旧习惯。

- **无风险利率（$R_f$）**：近似无信用违约风险、极短久期资产（如美国 1–3 个月国库券 T-Bill，实盘可用 `BIL` 近似）的收益率。
- **超额收益（Excess Return）** $= R_p - R_f$：策略收益减去无风险利率，回答“我承担风险后，比躺平买国库券**多赚了多少**”。
- **年化夏普比率（直觉口径）** $= \dfrac{R_p - R_f}{\sigma_p}$，其中 $\sigma_p$ 为年化波动率，衡量每承担 1 单位年化波动换来多少超额收益。（日频精确口径为 $\dfrac{\text{mean}(r_t - r_{f,t})}{\text{std}(r_t - r_{f,t})} \times \sqrt{252}$，W11D03 编程实现。）

**完整数字示范（为什么不能忽视 $R_f$）：**
1. **评估扭曲**：设策略甲年化收益 $R_p = 8\%$、年化波动率 $\sigma_p = 10\%$。
   - 若错误假设 $R_f = 0\%$：夏普 $= (8\% - 0\%) / 10\% = 0.80$（看似不错）。
   - 若实际高利率 $R_f = 5\%$：真实超额收益仅 $8\% - 5\% = 3\%$，真实夏普 $= 3\% / 10\% = 0.30$（承担 10% 波动仅比买国库券多赚 3%，性价比骤降）。
2. **空仓吃息（Cash Yield）**：设趋势策略上半年满仓赚 $+6\%$，下半年空仓。
   - 空仓干放 $0\%$ 现金：全年收益 $= +6\%$。
   - 空仓买入 `BIL`（假设半年收益 $+2.5\%$）：全年复利收益 $= (1 + 0.06) \times (1 + 0.025) - 1 = 1.0865 - 1 = +8.65\%$，多出 **2.65 个百分点**！

### 3. 从纯 Python 循环切换到 `pandas / numpy`

前 10 周用 `list[dict]` + `for` 循环是为了把账本机制看透。现在要同时处理 7 只 ETF × 4,400+ 交易日（超 3 万个数据点），行业标准做法是用 `pandas.DataFrame` 做**向量化运算**（一次对整张表运算，无需手写逐日循环）：

```python
import pandas as pd

# 行索引是交易日，每一列是一只 ETF 的复权收盘价
prices = pd.DataFrame({
    "SPY": [100.0, 110.0, 99.0],
    "TLT": [100.0, 98.0, 102.9],
}, index=["D1", "D2", "D3"])

# 一行代码算出所有资产的逐日简单收益率：(今日价 - 昨日价) / 昨日价
returns = prices.pct_change()
```

输出 `returns`：
- `D1` 行两列都是 `NaN`（缺失值，因为没有前一天价格，**绝不自动填 0**，与 W08D01 纪律一致）；
- `D2` 行：`SPY = (110 - 100) / 100 = +0.10 (+10%)`，`TLT = (98 - 100) / 100 = -0.02 (-2%)`；
- `D3` 行：`SPY = (99 - 110) / 110 = -0.10 (-10%)`，`TLT = (102.9 - 98) / 98 = +0.05 (+5%)`。

### 4. W11D01 课中答疑补充（2026-11-25）

- **通缩衰退（2008）中股跌与长债涨的关系**：并非“股跌直接导致债涨”的单一因果，而是同一宏观根因（经济衰退 + 通胀低 + 央行紧急降息）触发的两条传导链：衰退压低企业盈利→股市跌；降息使高息旧长债变抢手（期限越长、久期放大效应越强）→`TLT` 大涨，再叠加避险资金（Flight to Safety）流入强化负相关。
- **高通胀加息（2022）中各资产分化**：核心冲击源是“通胀失控→激进加息”。利率飙升直接压低高久期旧长债价格（`TLT` 暴跌），同时推高折现率并压制远期盈利估值（`SPY`/`QQQ` 大跌，科技股尤甚，形成“股债双杀”）；而 `BIL` 仅持 1–3 个月超短债，久期极短几乎不跌且迅速滚动买入更高息新债；`GLD` 的抗通胀/避险属性与加息压力相互对冲，走势相对平稳。
- **夏普率、$R_f$ 与 `BIL`**：夏普率 $= (R_p - R_f)/\sigma_p$ 衡量“每承担 1 单位年化波动换来多少超额收益”；“无风险”指本币口径下**违约风险极低（主权信用）+ 价格波动极低（极短期限，如 1–3 月 T-Bill）+ 高流动性**，长债因利率风险大不属于无风险资产；`BIL` 类似随市场利率浮动的超短期活期/定存替代品，但作为交易所 ETF 可随时买卖无罚息、自动滚动换新债，是量化账户空仓吃息的真实可交易工具。

### 2. 三个真实发现

1. **`close` 和 `adj_close` 差别巨大**：BIL 用 `close` 算的 17.5 年累计涨幅是 −0.2%，用 `adj_close` 算是 +22.1%；TLT 分别为 +2.0% 和 +72.3%。债券类 ETF 每月派息，派息当天价格会下调相应金额，所以只看 `close` 会漏掉利息。
2. **RF 日频文件精度不够**：源文件只保留两位小数（单位为百分比），最小一档 0.01%/日，约合年化 2.5%。2017 年 1 个月国库券年化收益约 0.79%，按日拆分约为 0.003%/日，四舍五入后变成 0.00。改用月频文件（一档 0.01%/月，约合年化 0.12%），自己按交易日数拆成日频。
3. **两次下载哈希不同不等于数据变了**：相隔 4 分钟的两份下载，`adj_close` 的相对差在 2×10⁻⁶ 以内，其他列完全相同。比较浮点数据要设容差，例如 `np.isclose` 或 `assert_allclose`。

### 3. 月度 RF 拆成日度：公式与小例子

- **输入**：某月收益 $r_m$（小数/月）和当月实际交易日数 $n$。**输出**：当月每个交易日的收益 $r_d$。
- **公式**：$r_d=(1+r_m)^{1/n}-1$。这样 $n$ 天连乘 $(1+r_d)^n$ 恰好还原 $1+r_m$。
- **例子**：2024 年某月 $r_m=0.42\%$，$n=21$，$r_d=1.0042^{1/21}-1\approx0.01996\%$/日。若直接用 $0.42\%/21=0.02\%$，连乘 21 天后会略高于 $0.42\%$。差异极小，但复利口径应该严格还原月收益。

### 4. 编码题需要的 `pandas` 工具（示例数据与题目不同）

```python
import pandas as pd
df = pd.DataFrame({'a': [1, 5, 3], 'b': [4, 2, 3], 'c': [0, 9, 3]},
                  index=pd.to_datetime(['2024-01-30', '2024-01-31', '2024-02-01']))

df[['a', 'b']].min(axis=1)          # 每一行在 a、b 两列中取较小值 -> [1, 2, 3]
mask = (df['c'] > df['a']) | (df['c'] == 0)   # 逐行布尔比较；| 表示“或”，& 表示“且”，两边必须加括号
mask.rename('my_flag')              # 给 Series 改名

s = df['a']
r = s.pct_change()                  # [NaN, 4.0, -0.4]
r.dropna()                          # 去掉 NaN（只用于报告，不改原数据）
r[r.abs() > 1.0]                    # 布尔索引：只留绝对值 > 1 的行，保留正负号

months = df.index.to_period('M')    # PeriodIndex(['2024-01', '2024-01', '2024-02'])
months.value_counts()               # 每个月出现几次：2024-01 -> 2，2024-02 -> 1
pd.Series(months).map(months.value_counts())   # 把“当月天数”按位置映射回每一行 -> [2, 2, 1]
monthly = pd.Series([0.1, 0.2], index=pd.PeriodIndex(['2024-01', '2024-02'], freq='M'))
monthly.reindex(months)             # 按每行所在月份取对应值 -> [0.1, 0.1, 0.2]；不存在的月份得到 NaN
months.isin(monthly.index).all()    # 是否所有月份都能找到对应值
```

注意：`.to_numpy()` 可以取出不带索引的数组，用来避免两个索引不同的 Series 在运算时按索引错位对齐。

### 补讲：`pandas` 最小地图（B3 所需，2026-11-27）

1. **Series = 一列数值 + 每个值的标签（索引）**，类似有顺序、能整体运算的 dict。`s.loc[标签]` 按标签取值。
2. **两种时间索引**：`DatetimeIndex` 表示具体某一天；`PeriodIndex(freq='M')` 表示一整个月。`日期索引.to_period('M')` 把每一天换成它所属的月份标签。
3. **向量化运算**：`(1 + s) ** 0.5` 会对每个元素分别计算，不需要写 for 循环。
4. **批量查表**：`s.reindex(一组标签)` 按顺序逐个查表，标签可以重复，查不到的返回 NaN。`一组标签.isin(s.index)` 逐个回答"表里有没有"，后面加 `.all()` 表示"是否全都有"。
5. **计数并映射回每一行**：`标签.value_counts()` 统计每个标签出现几次；`pd.Series(标签).map(计数表)` 把次数按位置填回每一行。
6. **索引对齐陷阱**：两个 Series 相加时按标签配对，而不是按位置。例如 `x` 的标签是 a、b，`y` 的标签是 b、c，`x + y` 的结果是 a→NaN、b→12、c→NaN。用 `.to_numpy()` 取出纯数组，就能按位置计算。

B3 的分步路线：① 每个交易日对应的月份 `months` → ② 检查 `months` 是否都在 `rf_monthly` 里，缺失就 `raise ValueError` → ③ 查出每天对应的 r_m → ④ 每天对应的 n → ⑤ 套公式，组装成 `pd.Series(值, index=trading_dates, name='rf')`。

**课中答疑：每个交易日都按月收益算一次，算不算重复计算？（2026-11-28）**：在"计算"层面确实有重复：同一个月里 n 个交易日的公式和结果都一样，也可以先按月算出 211 个日收益，再填回 4,427 个交易日。但在"收益"层面没有重复计入：每天只分到 $r_d$，n 天连乘后恰好还原 $1+r_m$。例如 2 月 $r_m=0.1\%$、n=3，$r_dpprox0.033322\%$，3 天复利后正好是 0.1%。真正的重复计入，是把整月的 0.1% 原封不动地赋给每一天，那样 3 天复利会变成 0.3003%。测试 `test_compounds_back_to_month` 就是专门防这个错误的。

### 补讲：RF 到底是什么（2026-11-28，教学遗漏）

- **1 个月期国库券**：美国政府发行的 1 个月短期借条。例如今天花 99.6 美元买入，1 个月后政府还 100 美元，这个月赚约 0.4%。它几乎不可能违约，期限又短，价格几乎不波动，所以被当作"无风险"资产。
- **RF**：Ken French 教授整理公开的一张表，每个月一行，记录"这个月持有 1 个月期国库券能赚多少"。开发期实例：2017-06 为 0.06%，2018-06 为 0.14%，2023-06 为 0.40%，2024-12 为 0.37%。它是一份**记录**，不是商品，买不到，就像没人能买到"物价指数"。
- **BIL**：一只真实存在、可以在券商买卖的 ETF。基金公司用你的钱买 1–3 个月期国库券，到期后再买新的，并收取管理费。所以 BIL 的收益大致跟着 RF 走，但每年少一点（开发期 17 年累计少 1.29 个百分点）。
- **对应关系**：W11D01 学的 $R_f$（夏普公式里减去的那个数）以后不再由题目随手给出（如 4%），而是从 RF 表中取当期的真实值。

### P2：从每日收益率还原累计净值——`cumprod()`（2026-11-28）

**用途**：你在 P1 追问里手算的"每天相对 D1 的累计收益"，就是 W09 的标准化净值减 1。`pandas` 有两条路能算出它：

```python
total = pd.Series([100, 100, 100, 102, 99], index=['D1','D2','D3','D4','D5'], name='total')
total / total.loc['D1'] - 1     # 路 1：直接除以首日（P1 学过的整列运算）-> 0, 0, 0, 0.02, -0.01
r = total.pct_change()          # 每日收益率（W11D01 学过）-> NaN, 0, 0, 0.02, -0.029412
(1 + r).cumprod()               # 路 2：逐日累乘（新）-> NaN, 1.00, 1.00, 1.02, 0.99
```

- **`cumprod()` = 累乘**：第 k 个结果 = 前 k 个值相乘。例：`[2, 3, 4]` → `[2, 6, 24]`。
- **为什么要累乘 `1 + r`**：W01 复利：先涨 2% 再跌 2.94%，总倍数 = 1.02 × 0.970588 ≈ 0.99，不能把收益率直接相加。
- **首行 `NaN`**：`pct_change()` 首行没有前一天，是 NaN；`cumprod()` 遇到 NaN 跳过并保留 NaN，从 D2 开始累乘。D1 的净值本来就是 1，以后需要时再补，不填 0。
- **为什么还要路 2**：回测里我们先得到的是**策略每天的收益率**（不同日子持仓不同），没有现成的"总价值"列，只能用累乘还原出净值曲线。

**P2 小变式（先预测、再运行核对）**：用 W11D01 的例子 `nav = pd.Series([100.0, 110.0, 99.0], index=['D1','D2','D3'])`。
1. `r = nav.pct_change()` 的 3 个值？

### P4（上）：用布尔比较生成目标份数（2026-11-28）

P4 分两步：本节先讲"信号 → 目标份数"，下一节再讲 `shift(1)`（晚一天执行）。

**用途**：W10 规则是"收盘价**严格高于**三日均线 → 目标 1 份；等于或低于 → 0 份"。`pandas` 里两个 Series 用 `>` 比较，会逐日得到 `True/False`（布尔值）。

```python
close = pd.Series([48, 51, 54, 57, 54], index=['D1','D2','D3','D4','D5'], name='close')
ma3 = close.rolling(3).mean().rename('ma3')     # NaN, NaN, 51, 54, 55
above = close > ma3                             # False, False, True, True, False
target = above.astype(int).rename('target')     # 0, 0, 1, 1, 0
```

- `close > ma3`：按同一天比较，D5 的 54 > 55 不成立，得到 False。
- `.astype(int)`：把 True 转成 1、False 转成 0，正好是目标份数。
- **NaN 参与比较时一律得到 False**：D1、D2 均线还算不出，比较结果是 False，目标 0 份，和 W10"等待、不持有"一致。注意这是规则碰巧一致，以后遇到别的规则要单独确认。

### P4（下）：晚一天执行——`shift(1)`（2026-11-28）

**用途**：W10 时间线是"第 t 天收盘后算出目标 → 第 t+1 天开盘才成交"。所以**第 t 天实际持有的份数 = 第 t−1 天收盘时的目标**。`shift(1)` 把整列往后挪一天：

```python
target = pd.Series([0, 0, 1, 1, 0], index=['D1','D2','D3','D4','D5'], name='target')  # W10 原例
position = target.shift(1).rename('position')    # NaN, 0, 0, 1, 1
```

| 日期 | `target`（当天收盘算出） | `position`（当天开盘后实际持有） | W10 账本 |
| --- | --- | --- | --- |
| D1 | 0 | NaN（没有前一天的信号） | 0 份 |
| D3 | 1 | 0 | D3 收盘才发出买入信号，仍为 0 份 |
| D4 | 1 | 1 | D4 开盘按 55 买入，变成 1 份 |
| D5 | 0 | 1 | D5 收盘才发出卖出信号，D5 仍持有 1 份（D6 开盘卖出） |

- 第一行因为没有来源，变成 NaN；因此整列变成小数类型（显示为 `0.0`、`1.0`）。D1 的 NaN 怎么处理，留到 P5 账本再说。
- `shift(1)` 只是把值挪了位置，标签不动。

**P4（下）小变式 ✅（2026-11-28）**：四问全对（`>=` 时 D4 目标为 1；NaN、0、0、1；D4 持有 1 份，来自 D3 收盘信号；不 shift 等于用当时还不知道的数据，结果失真）。补充术语：这种错误叫**前视偏差**（look-ahead bias）。例如 W10 原例里 D3 就算持有 1 份，会白赚 D2→D3 从 51 涨到 54 的那 3 美元，而这段涨幅要到 D3 收盘才知道。回测通常因此显得比实际更好。

### P5：`DataFrame`——把几列放进同一张账本表（2026-11-28）

**用途**：P1–P4 我们算出了 `close`、`ma3`、`target`、`position` 四个 Series，标签都是 D1–D5。`DataFrame` 就是**共用同一组行标签的多列 Series**，像 W10 的逐日账本表一样一行一天、一列一个量。

```python
df = pd.DataFrame({'close': close})                     # 先用一列建表
df['ma3'] = df['close'].rolling(3).mean()               # 加新列：直接赋值
df['target'] = (df['close'] > df['ma3']).astype(int)
df['position'] = df['target'].shift(1)
print(df)
```
```
    close   ma3  target  position
D1     48   NaN       0       NaN
D2     51   NaN       0       0.0
D3     54  51.0       1       0.0
D4     57  54.0       1       1.0
D5     54  55.0       0       1.0
```

| 写法 | 含义 |
| --- | --- |
| `df['close']` | 取一列，得到的是 Series（P1–P4 学过的所有写法都能用） |
| `df[['close', 'position']]` | 取多列，注意是**两层方括号**（里面一层是列名列表），得到的还是 DataFrame |
| `df.loc['D4']` | 按行标签取一行（D4 这天的所有列） |
| `df['新列'] = ...` | 加新列。这是**赋值语句**，会直接改变 `df`，和 `rename` 这类"返回新对象"的方法不同 |
