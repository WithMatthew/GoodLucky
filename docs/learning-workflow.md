# 学习与续接流程（v2.1）

这份流程用于保障跨会话、跨工具稳定续学。学习状态以本地文件为准，不依赖聊天记忆或自然日期推算。

## 核心文件分工

| 文件 | 职责 | 更新时机 |
| --- | --- | --- |
| [AGENTS.md](../AGENTS.md) | 仓库协作、数据安全、风控与教学底线 | 工作方式有实质变更时 |
| [learning-plan.md](learning-plan.md) | 24 周学习路线、阶段目标与验收标准（v2.1） | 课程结构调整时 |
| [learning-progress.md](learning-progress.md) | **唯一当前状态依据**：续学检查点、能力矩阵、错题/巩固本、简洁课次台账 | 每轮有实质进展时 |
| [learning-process.md](../learning-process.md) | 供外部工具/提醒读取的轻量同步摘要 | 每次更新进度后同步 |

## 新会话恢复顺序

1. 读取 `AGENTS.md`（若未自动加载）。
2. 读取 `docs/learning-progress.md` 的“当前状态”与“续学检查点”。
3. 读取 `docs/learning-plan.md` 对应周及对应课件（如有）。
4. 用一句话说明恢复到哪一课、哪一步，直接推进：有待答题先接续，有已答未评先反馈，前课完成则直接进入下一课。无需反复询问已记录的背景信息。

## 教学与实践原则（W11 起实战升级）

1. **讲清机制，再动手做**：新概念先说明它解决什么问题、输入/窗口/单位与核心机制，用一个极小完整例子跑通，再让学习者动手。出题前逐问核对讲解是否已覆盖所需步骤，教学遗漏先补讲、不记错题。
2. **从“手算问答”升级为“代码驱动 + 批判分析”**：
   - W01–W10 已夯实基础手算能力。W11 起仅在新指标/新算法首次引入时保留极小手算核对，**减少纯重复性的四则运算问答**。
   - **学习者主导核心编程**：AI 提供数据准备骨架与测试框架，学习者亲自编写或补全核心策略逻辑（信号、权重、回测、指标、验证、风控），先说明预期再运行核对。AI 生成代码运行通过不等于学习者已掌握。
3. **高效推进，不凑时长**：达到当课核心理解与代码验证要求即可结课；补课不增加计划总课次，也不按预算填写真实用时。
4. **W16 起模拟盘巡检融合**：模拟盘上线后，每周固定安排一次约 10 分钟的“模拟盘巡检 + 账本核对”，独立记录于模拟盘日志，不打断主线学习节奏。

## 轻量进度保存规范（反膨胀）

用户已授权保存普通学习记录，无需每轮询问：

1. **保持简洁、拒绝“笔录化”**：`docs/learning-progress.md` 只记录恢复所需的关键信息——当前检查点、本课掌握证据、真正需要巩固的薄弱点（不记录无关紧要的标点或措辞微调）、待答题全文或课件锚点、实际用时。
2. **禁止刷屏免责声明**：科研边界与非实盘约束已在 `AGENTS.md` 与 `learning-plan.md` 顶层声明，不在每课进度行重复粘贴。
3. **发出待答题即落盘**：每轮发出需要作答的练习或编程任务时，同步在“续学检查点”保存题目要点或对应课件链接。
4. **双文件同步核对**：更新 `docs/learning-progress.md` 后，同步更新根目录 `learning-process.md`，核对完成课次、累计用时、检查点与下一步一致后再回复已保存。文件维护本身不增加课次或学习时长。
5. **历史按阶段归档**：每完成一个大阶段（如 W01–W10、W11–W15），可将冗长过程记录归档至 `docs/archive/`，保持主进度文件清爽易读。

## 常用指令约定

| 用户说 | 助手应做 |
| --- | --- |
| 继续学习 / 继续今天的学习 | 按检查点一句话说明恢复位置并直接推进 |
| 继续学习，今天有 X 分钟 | 按可用时间裁剪当次任务范围 |
| 巡检模拟盘（W16 起） | 执行本周模拟盘数据拉取、信号检查与账本核对 |
| 复习上次 | 针对最近一课与错题本薄弱项做简短回顾，不增加课次 |
| 今天先到这里 / 保存进度 | 立即保存当前断点与待办，确认写入后回复 |
| 查看学习进度 | 汇报当前位置、累计用时、能力进度与下一步，不自动开新课 |
