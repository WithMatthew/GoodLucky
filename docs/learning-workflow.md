# 学习与续接流程

这份流程让学习能跨聊天、跨 Codex 启动继续。仓库中的进度文件负责保存状态，课件负责保存教学内容，AGENTS.md 负责说明何时读取它们。已经写入的本地文件不需要依赖原聊天才能使用。

## 文件各自负责什么

| 文件 | 用途 | 更新时机 |
| --- | --- | --- |
| [AGENTS.md](../AGENTS.md) | 教学与续接的固定约定 | 用户改变工作方式时 |
| [学习计划](learning-plan.md) | 24 周范围、顺序和验收要求 | 学习安排有实质调整时 |
| [学习进度](learning-progress.md) | 当前状态、检查点、学习证据、实际用时 | 每轮有实质进展时 |
| [课件目录中的第一周任务](lessons/week-01.md) | 对应课次的内容与练习 | 备课或修正材料时 |

当前进度只在 learning-progress.md 维护，不在 README、AGENTS.md 或其他文件复制动态课次和累计时长。课件中的建议日期不能覆盖实际完成记录。

## 新会话如何恢复

1. 确认当前工作目录是这个项目，并读取 AGENTS.md。
2. 读取 learning-progress.md 的当前状态、续学检查点和复习内容，再读取本流程及计划、课件中对应部分。
3. 从最新已保存的状态确定要做的事：有待答题就恢复该题，有已答未评反馈就先反馈，待补习就补习，前课完成且新课未开始就进入新课。
4. 用一句话告知用户恢复位置。不要重新询问已记录的编程基础、市场方向和学习节奏，也不要要求复制以前的聊天。
5. 按用户本次可用时间安排内容；没说明时沿用每日 60 分钟预算。无需等待用户确认恢复位置才开始。

一课使用固定编号，例如 W01D01 表示第 1 周第 1 天。跨自然日继续同一课仍使用原编号；一次学完或补习多次，都只计为一个完成课次。

若文件不存在或内容冲突，先查现有课件和历史记录能否恢复；只有真正缺失的事实才向用户询问。不能把进度重置为零，也不能用已经过去多少天推断学到了哪一课。

## 每课教学顺序

按“简短复习、解释用途与运作过程、串联概念关系、完整示范、用户小步练习、反馈与验收、保存”推进。新概念不能只给定义就要求用户自行解释机制；先以一个贯穿的例子讲清谁持有什么、发生什么变化、为何产生结果。预测题只用于已有知识可推导的内容。用户说不知道时，先找出缺失环节并直接解释或换例子，不重复要求复述。用户要求讲解时先完整回应，不在同轮强加验收题；讲解本身不计为掌握证据。2026-10-17 用户明确要求按此方式调整教学。

用户进一步要求核心基础非常细致，避免含糊：每次聚焦少数相关概念，用贯穿例子说明定义、角色关系、因果机制与适用边界；明确哪些是现实定义、哪些是简化假设。解释中及时区分数量、单价、总价值，不以大量术语或重复考问代替教学。

验收以计划和课件为准。区分已经掌握、需要再练习、尚未讲到，不能因为 Codex 生成了代码或解释，就把用户标记为已掌握。达到当课要求即可结束，不为凑满 60 分钟强行加课。

出题与批改时核对实际教学范围：仅列举过名词或原因，不算已完整讲授其机制；用户指出未获对应教学时先核对课件，属于教学遗漏的内容先补讲，不记为用户错题，也不临时增加结课门槛。2026-10-18 用户指出此前未详细讲解基金持仓/权重为何可能与指数不同，已据此纠正记录。

用户提出澄清、修正或学习偏好时，将它融入当前课次。已澄清的问题及时从“未解决误解”中移除。用户问进度或要求维护流程时，完成该请求，不自动推进课程。

## 每轮怎样保存

用户已授权保存必要的学习记录，不用每轮再问是否保存。在本轮结束前执行相关步骤：

1. 更新本轮已经确认的答题摘要、纠正结果和掌握证据，不捏造作答或补足尚未完成的任务。
2. 更新续学检查点，写清课次、状态、下一环节，以及下一次具体要做什么。
3. 如果本轮要请用户作答，把准备发出的题目全文、必要数据、已给提示和相关文件路径保存到“当前待回答题目”。若资料较长，存入对应课件并在检查点链接；不能只写“继续上一题”。
4. 用户只回答了部分题目时，保存已答摘要并保留剩余题目。未判定的答案标为待反馈，不能计为已掌握；下一次优先完成反馈。
5. 写入后读取相关字段核对。确认成功后才告知已保存；若写入失败，说明具体未保存部分并提供可复制的续学摘要。

普通讲解也要保存已经覆盖的概念和下一练习，避免重开后重讲整课。每轮记录以恢复所需的内容为限，不抄录整段聊天。家庭开支逐项明细、凭据和账户记录不复制进学习日志；练习优先使用虚构数字。

## 结课与用时

达到课件的完成条件后，将本课标为完成，更新完成课次、验收证据和下课检查点。第 5 天完成后才进入下一周；补课不增加计划总课次。

实际用时采用用户提供的值，允许记录“约 30–40 分钟”。同课多轮问答的整课用时只累计一次；补充或更正时长时替换原数值，不再次相加。不拿聊天墙钟时间、计划预算或维护文件所花的时间冒充学习时长。无法确定时保留“待确认”，下次合适时补记。

结课回复简要说明学会了什么、需要复习什么、是否保存成功，以及下次从哪里开始。课次完成与实际用时确认可以分开进行。

## 暂停与关闭

用户说“今天先到这里”“保存进度”或准备关闭时，立即保存已确认内容和未完成问题。未达到验收条件的课保持暂停或待补习，不自动结课；下次从保存的环节继续。

用户不必等整节课结束才退出。每轮落盘的检查点能保留已经处理的进展；如果在回复处理或写入期间强制关闭，只能恢复到最后一次成功保存的位置，未保存内容可能需要补充。

重新打开同一个本地项目即可使用原聊天或新聊天续学。换设备时需携带项目文件，本流程没有配置跨设备同步或后台退出钩子。

## 常用说法

| 用户说 | Codex 应做 |
| --- | --- |
| 继续学习 | 读取检查点，说明恢复位置并继续 |
| 继续学习，今天有 30 分钟 | 从检查点继续，把本次内容控制在可用时间内 |
| 复习上次 | 复习最近一课和记录的薄弱点，不重复增加完成课次 |
| 今天先到这里，保存进度 | 保存当前环节和待办，报告保存结果 |
| 查看学习进度 | 报告当前课次、实际用时、待复习内容和下一步 |

若环境未自动加载仓库说明，用户可说：“请读取 AGENTS.md、docs/learning-workflow.md 和 docs/learning-progress.md，按续学检查点继续学习。”

Codex 对项目说明的发现方式可查阅 [OpenAI 的 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。官方文档说明了启动时读取项目指引的机制；本仓库用这些指引要求后续会话主动读取学习进度，不能把指引加载本身当作完整聊天记忆。[OpenAI 项目与聊天说明](https://learn.chatgpt.com/docs/projects?surface=app)
